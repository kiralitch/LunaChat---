# LunaChat 演示脚本（约 12 分钟）

> 目标：在一台机器上开 **一个服务端 + 两个客户端**，把九大功能按"能看到的顺序"串起来。
> 每一步都给了「操作」和「讲解要点」，照着点即可；末尾附兜底方案与常见问题。

## 0. 演示前 10 分钟检查

| 检查项 | 命令 / 操作 | 通过标准 |
| --- | --- | --- |
| MySQL 在跑 | `mysql -h127.0.0.1 -uroot -p -e "show databases;"` | 能看到 `luna_chat` |
| 表结构就绪 | `mysql ... -e "source sql/schema.sql"` | 无报错（重复执行会提示 duplicate column，可忽略） |
| 数据库密码 | `Server/config.ini` 的 `[database] password` | 与 `mysql -p` 输入的一致 |
| 服务端 | 双击 `x64\Debug\Server.exe`（或 `dist\LunaChat-Release\Server.exe`） | 管理窗口出现，日志显示 `listening on 0.0.0.0: 8888` |
| 两个客户端 | 两次启动 `Client.exe` | 两个登录窗口，标题都是"LunaChat 月之音" |
| 演示账号 | `luna / 123456`、`star / 123456` | 都能登录 |
| 音效文件 | `sounds\` 下有 `message.wav` `online.wav` `match.wav` `activity.wav` | 缺哪个补哪个（见第 10 节） |
| 麦克风 | 设置页"输入电平"点"测试电平" | 进度条随说话跳动 |
| 分辨率 | 两个窗口并排放，1280×800 以上 | 不用滚动就能看到会话列表和聊天区 |

> 建议先把两个客户端分别放在屏幕左右两侧，演示时不用来回拖窗口。

## 1. 开场（30 秒）

**操作**：不点任何东西，停留在登录页。

**讲解**：
> LunaChat（月之音）是一个基于 Qt 5.15 + C++17 的局域网即时通讯系统。
> 客户端负责界面与本地能力，服务端是单进程多会话的 QTcpServer，数据落 MySQL。
> 通信统一用「4 字节大端长度 + JSON」的自定义帧，共 87 种消息类型。

## 2. 登录与注册（1 分钟）

**操作**：
1. 左窗口用 `star` 登录，右窗口用 `luna` 登录。
2. 随意点一下"注册"，展示注册对话框后关掉（不真的建号）。

**讲解**：
> 密码在服务端做 SHA-256 后入库，不存明文；登录成功后服务端把 userId 绑定到这条 TCP 会话，
> 后续所有消息都靠它鉴权。

## 3. 好友与"上线提示音"（1.5 分钟）

**操作**：
1. 在 `luna` 窗口点右上角"加好友"，选择 `star` 发送申请。
2. 切到 `star` 窗口，好友列表里同意申请。
3. **让 `star` 下线再登录**（关闭窗口重开），此时 `luna` 端应响一声"好友上线音"。

**讲解**：
> 好友关系是双向写入 `friend` 表；上线提示音由 `MainWindow::playSound("online")` 触发，
> 播放器统一收敛在 `Core/SoundPlayer.h`，音量取设置页的值。
> 如果这台机器没声音，看 `sounds\online.wav` 是否存在——缺文件是静默失败的，不会弹框。

## 4. 私聊、群聊与历史消息（2 分钟）

**操作**：
1. `luna` 左栏点"校园大厅"（群聊），发一句"晚上一起自习吗？"。
2. `star` 端应实时收到，气泡靠左、头像正确。
3. `star` 私聊回复 `luna`，展示左右对齐与时间。
4. 在聊天区向上滚动，展示历史消息分页加载。

**讲解**：
> 私聊对方离线时，服务端把整帧塞进 `offline_message`，登录时一次性补推；
> 群聊则广播给所有在线成员。气泡、头像、时间戳都由 `ChatPage` 按消息类型渲染。

## 5. 文件与语音（2 分钟）

**操作**：
1. 在私聊窗口点"发送文件"，选一个 3–5MB 的文件，等进度条走完，`star` 端点开接收到的文件。
2. 再选一个 12MB 文件，展示"单文件 ≤10MB"的本地拦截提示。
3. 点"语音"，按钮变成"停止录音"，说一句"收到，晚上见"，再点一次结束并发送。
4. `star` 端点语音条的播放按钮。

**讲解**：
> 文件和语音都按 64KB 原始数据分块、base64 后走同一套帧，避免大包把 1MB 上限撑爆；
> 服务端只存元信息和落盘路径，二进制在 `received/` 目录。
> 语音走 16kHz 单声道 PCM，录音短于 300ms 会自动取消。

## 6. 群管理与共享文件夹（2 分钟）

**操作**：
1. 点聊天头部的"群资料"，展示成员列表、公告、群头像。
2. 点"邀请成员"，把 `star` 拉进一个新建的群（演示建群 + 邀请）。
3. 以 `luna`（群主）身份踢掉一个测试成员，展示权限校验。
4. 点"共享文件夹"，新建目录 `课件`，上传一个文件；`star` 端刷新后下载。

**讲解**：
> 角色分 owner / admin / member，服务端每个敏感操作都查 `isGroupAdmin`；
> 共享文件夹的目录和文件存在服务端 `group_files/`，客户端只拿列表和分块。

## 7. 朋友圈（2 分钟）

**操作**：
1. 点左侧"朋友圈"，展示时间线。
2. 发布一条带 3 张图的动态；点图片看大图。
3. 用 `star` 点赞 + 评论，`luna` 端实时刷新计数。
4. 点右上角背景按钮换一张朋友圈背景。

**讲解**：
> 图片按需拉取（`moment_image`），列表只带索引，避免一次把九张图全塞进一帧；
> 点赞有唯一键，重复点就是取消；删除是软删，数据库留痕。

## 8. 随机匹配 + "匹配成功音"（2 分钟）

**操作**：
1. 两个客户端都点左侧"随机匹配"，模式都选"文本"。
2. 先点 `luna` 的"开始匹配"（进入排队），再点 `star` 的"开始匹配"。
3. 配对成功瞬间：两端各响一声"匹配成功音"，页面进入临时会话。
4. 互发两条消息，然后一方点"结束会话"，另一方收到结束提示。

**讲解**：
> 服务端维护文本 / 语音两条等待队列，配对成功生成 UUID 会话，双方收到 `match_result`；
> 15 秒无人应答会回 `match_timeout`；任一方掉线，服务端会结束会话并通知对方，避免"对着空气聊天"。

## 9. 群活动 + "活动提醒音"（2 分钟）

**操作**：
1. 回到"校园大厅"群，点聊天头部的"群活动"。
2. 用 `luna`（群主）发布活动：标题"周末桌游局"，时间选一小时后，人数 10。
3. `star` 端应收到群内通知并响一声"活动提醒音"；在活动列表里报名。
4. 展示报名人数 +1，再点取消报名，人数 -1。
5. 用非管理员账号试一次"发布活动"，展示 403 提示。

**讲解**：
> 活动状态由服务端每分钟巡检推进：到开始时间 `published → ongoing`，过结束时间 `→ ended`；
> 取消活动只能由群主 / 管理员操作，报名要求状态是 published 且未满员。

## 10. 设置页与打包产物（1.5 分钟）

**操作**：
1. 点左侧"设置"，展示四行音效：每行是「启用复选框 + 选择文件 + 当前文件名」。
2. 点"匹配成功音"那行的"选择文件"，选一个 wav，行内文件名立即更新。
3. 切"日间 / 夜间"主题，拖动音量条，点"保存设置"。
4. 关掉客户端重开，展示设置仍在。
5. 打开资源管理器，展示 `dist\LunaChat-Release\`：exe + Qt 运行库 + `sounds\` + `backgrounds\` + `sql\`。

**讲解**：
> 设置统一走 `QSettings`；音效文件直接替换程序目录 `sounds\<kind>.<ext>`，
> 所以打包后仍可用，不需要重新编译。部署用 `tools\package.ps1` 一条命令：编译 + windeployqt + 拷资源 + 打 zip。

## 11. 收尾（30 秒）

> 项目一共 16 张表、87 种消息类型，客户端 14 个界面类、服务端 9 个 Handler。
> 核心功能已逐项验证，新增的匹配 / 活动提示音与合并后的设置行是最后一轮改动，
> 打包与论文素材（架构图、帧格式图、ER 图、状态机、测试用例、截图清单）已放在 `docs/`。

## 兜底方案

| 万一 | 处理 |
| --- | --- |
| 服务端连不上数据库 | 改 `config.ini` 后重启 Server；讲解时改口"先看管理端日志" |
| 某个客户端登录不上 | 关掉重开；服务端管理窗口能看到 `login ok` 日志 |
| 没声音 | 先看 `sounds\` 是否有文件，再看设置页开关和音量，最后看系统音量合成器 |
| 匹配 15 秒超时 | 正常现象，直接说"超时会提示重试"，再点一次即可 |
| 语音录不进去 | 设置页换"录音设备"，点"测试电平"确认有输入 |
| 动画卡顿 | 关闭录屏软件的硬件加速，或降低分辨率 |

## 常见提问（提前准备）

1. **为什么不用 HTTP/WebSocket？** 课程要求自研协议；长度前缀 + JSON 比文本分隔符更容易处理半包/粘包，
   也便于把文件分块塞进同一套帧。
2. **1MB 上限怎么来的？** 单帧防恶意大包；64KB 分块 base64 后约 87KB，留足余量。
3. **并发怎么做？** 单进程事件循环 + 每连接一个 `ClientSession`，业务层无阻塞 IO，
   MySQL 操作用预编译 SQL，避免注入。
4. **消息可靠性？** 在线直接转发，离线落 `offline_message`，登录补推；文件/语音按块传，断线可重发。
5. **音效为什么单独抽 `SoundPlayer`？** 避免每个页面都 new `QMediaPlayer`、都去拼路径；
   现在页面只调 `SoundPlayer::play("match")`，缺文件静默，不打断主流程。
